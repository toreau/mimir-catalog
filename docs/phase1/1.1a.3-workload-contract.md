# Phase 1.1A.3 — Workload and Metrics Contract v1

Normative contract for the storage-engine-neutral benchmark experiment that
1.1A.4-1.1A.8 will execute. The Markdown explains the semantics; the machine-
readable file `benchmarks/workload-contract-v1.json` freezes the executable
parameters. Where prose and machine-readable parameters conflict, implementation
must fail review rather than guess precedence. This contract does not choose a
storage engine and contains no storage-candidate implementation.

## Scope

The contract defines logical workloads, deterministic probe generation and
ordering, expected-result oracles, workload identity, measurement semantics,
evidence schema and fairness rules for comparing storage candidates over the
accepted canonical corpus (id `511adb9ebd066f1d4d344b80171902d5`). It never
modifies the corpus and never requires the Wikidata source.

## Lexical-key decision (frozen)

Version 1 uses raw, exact `Lang + Value` equality. Logical equality is exact
ordinal / raw UTF-8 content equality; binary/case-sensitive, no normalization,
no case folding, no Unicode normalization, no diacritic folding, no stemming,
no `LookupValue`, no production-resolver semantics. `LexKind` is part of the
result, never part of the lookup key. Candidate implementations must not rely
on a locale-sensitive database collation. Normalized resolver indexing is a
later, separate resolver contract; this bake-off measures the storage layer on
the frozen raw lexical domain.

## Workload classes

Three classes, never merged into a composite score:

- Serving: S1 Concept point lookup, S2 exact lexical lookup, S3 lexical entries
  by QID, S4 P31 adjacency by subject, S5 P279 parent adjacency by subject.
- GraphClassification: G1 bounded P279 ancestry (client-orchestrated BFS),
  G2 batch classification-oriented structural access. Harness owns traversal;
  storage adapters expose only S5-style adjacency. Recursive SQL is not the
  workload.
- AnalyticalBuild: exactly eight logical operations: A1-Concept,
  A1-LexicalEntry, A1-InstanceOf, A1-SubclassOf, A2, A3, A4, A5.

## Exact operations

- S1 input QID; result Concept row or miss. Measured strata T1-only 4000,
  T2-only (observed) 4000, T1∩T2 4000, absent 4000. Correctness-only: all 20
  unobserved tail concepts.
- S2 input (Lang, Value); predicate `LexicalEntry.Lang == Lang AND
  LexicalEntry.Value == Value`; result (Qid, LexKind)* ordered Qid asc then
  LexKind ordinal asc. Strata by fanout over distinct (Lang, Value) keys:
  1 (4000), 2-5 (4000), 6-50 (2000), >=51 (380-key census,
  selectionMode all-eligible, expectedEligibleCount 380), miss (4000). The
  fanout   boundaries are frozen; a sampled pool that cannot supply its count is
  a HOLD, and the Fanout51Plus census must equal the observed population (380),
  never a reduced sample. S2 measured total is 14,380 (miss 4,000/14,380);
  S1-S5 measured serving total is 52,880.
- S3 input QID; result all lexical rows ordered Lang, LexKind, Value ordinal
  asc. Strata: T1 with >=1 lexical row 1500, T2-only with >=1 lexical row 1500,
  Concept present with 0 lexical rows 1000.
- S4 input T1 SubjectQid; result TargetQid* ascending. Strata: degree 0 (3000),
  degree 1 (3000), ordinary degree >=2 (3000), high-degree (500). high-degree is
  the 500 subjects with highest outgoing P31 degree; ranking degree desc, then
  deterministic workload-selection hash asc, then QID asc; excluded from the
  ordinary degree >=2 pool.
- S5 input SubjectQid; result TargetQid* ascending over P279 parents. Strata:
  degree 0 (3000), degree 1 (3000), degree >=2 (3000).
- G1: 500 starts (degree-1 250, degree>=2 250). BFS: single start at depth 0,
  parents at depth 1, maximum included depth 3, adjacency processed ascending,
  one visited set, no expansion at depth 3, start not automatically part of the
  result. Guard: 5000 distinct visited structural nodes; an oversized start is
  rejected during generation and replaced by the next ranked eligible start.
  Published probes therefore all have complete expected results within the
  guard.
- G2: one batch of 200 deterministic T1 concepts (100 with P31 degree 1,
  100 with P31 degree >=2). Per concept: S4 P31 targets, then G1-style P279
  ancestry to depth 3 for each target. Output is a deterministic per-input
  structural digest plus an overall batch digest. No classification decision.
- A1: full relation scans; result row count plus a MultisetFoldV1 digest.
- A2: count grouped by (Lang, LexKind), canonical order Lang, LexKind.
- A3: P31 target fanout (TargetQid, Count), canonical TargetQid ascending.
- A4: P279 target fanout, canonical TargetQid ascending, validated by
  digest/cardinality over the complete result.
- A5: one row per P31 target (TargetQid, Fanout, EnLabel?, NbLabel?) where
  labels are `LexKind == "label"` and Lang in {en, nb}; LEFT JOIN semantics
  (targets outside lexical remain present with null labels); canonical
  TargetQid ascending.

## MultisetFoldV1

Order-independent fold over a relation. Each logical row is canonical-encoded
and hashed with an explicit FNV-1a-64; accumulators are row count, unchecked
UInt64 sum(hash), UInt64 xor(hash), unchecked UInt64 sum(hash*hash); the final
digest is the SHA-256 of the canonical accumulator tuple. Independent of
physical row order, multiplicity- and content-sensitive, cheap, and identical
in the neutral oracle and the future harness. Physical row order is never
semantic.

## Probe generation and ordering

Selection domain `mimir-catalog-workload-v1`. SHA-256 ranking over canonical
selector bytes `UTF8(domain 0x1F operation 0x1F stratum 0x1F identity)`; QID
identity is the decimal QID, lexical identity is the unambiguous length-prefixed
encoding of (Lang, Value). Rank ascending by the full digest; tie-break by the
canonical identity. No RNG, no process hash. Each stratum is internally
SHA-ranked; strata are then interleaved round-robin in the frozen stratum order,
which becomes the published measured sequence. Every candidate receives the
identical sequence.

Misses: concept misses are generated from a separate miss domain and proven
absent from Concept; lexical misses from a separate miss domain and proven
absent from the (Lang, Value) domain; published misses carry their expected
zero-result oracle. Hit/miss mix is fixed by the frozen counts (S1 4000/16000
absent; S2 4000/14380 miss).

## Correctness

Candidate-neutral canonical outputs. Small/set outputs are sorted canonically,
encoded canonically and SHA-256'd; full scans use MultisetFoldV1; grouped/join
results are canonically sorted by their logical key and hashed. Every future
timed result is VALID/INVALID/TIMEOUT/ERROR; only VALID measurements enter the
1.1A.8 comparison. Wrong output is not a performance result.

## Measurement semantics (future candidate harness)

- Fresh-process/open and warm steady state are the only terms. OS filesystem
  cache is not forcibly evicted; no OS-cold-cache claims.
- Serving repetitions: 3. Per repetition: open a fresh adapter/process, run one
  complete untimed pass over the operation's exact measured probe sequence, run
  one complete timed pass, close. Warmup never enters measured statistics.
- Open/startup: open_ready and first_operation_after_open, 5 repetitions,
  never mixed into steady-state latency.
- Serving summaries per (operation, stratum, repetition): count, min, p50, p90,
  p95, p99, max, mean, throughput. p99.9 is excluded from v1. Do not pool
  heterogeneous strata for larger percentile samples. The authoritative
  cross-repetition summary is the median of the three repetition-level summary
  metrics (raw samples retained under gitignored candidate run evidence).
- Analytical: 3 repetitions each, wall time, rows/units processed, result
  cardinality, result digest, correctness status.
- G1 per-start latencies use the repetition model; G2 is one 200-concept batch
  per repetition (3).
- Build: 3 repetitions; wall, external peak RSS, managed-memory diagnostics,
  temporary disk peak, final persisted bytes, generated file count, config
  identity, result validation.
- Timeouts (evidence, never silently omitted): point op 5 s, G1 start 30 s,
  G2 batch 120 s, analytical 900 s, build 3600 s.

## Memory and disk

External peak RSS uses `/usr/bin/time -l` (existing project convention) on the
macOS benchmark environment; distinguish external peak RSS, process RSS
samples, and managed heap/allocation. Never label managed memory as RSS. Disk:
canonical corpus input bytes, candidate final persisted bytes (all indexes,
helper files, DB files, partitions, materialized structures), and temporary
build peak are separate. Candidate size excludes the canonical corpus, workload
artifacts, package caches and unrelated temp directories.

## Fairness and configuration

Candidates may use general indexes, sort orders, partitioning, compression and
materialized helper structures if built inside the measured build, included in
final size, persisted as part of the candidate, general to the logical
workload, and not keyed to the probe list. Precomputed answers for measured
probes, probe-specific indexes and adapter-level memoization are prohibited.
Each of 1.1A.4-1.1A.7 gets one reviewed baseline configuration frozen before
measurement; aggressive tuning is separate evidence and never silently replaces
baseline. Compression algorithm and settings are recorded on every run.

## Identity, artifacts, publication

workload_id is the full lowercase 64-hex SHA-256 over canonical immutable
content: contract versions, corpus id, selection/miss domains, strata
(counts and order), G1/G2 semantics, canonical-encoding and fold versions,
warmup/repetition/timeout semantics, and input artifact identities (T2 and the
four Parquet SHA-256 values plus the Phase-0 fixture SHA). No timestamp or
absolute path is part of identity or any authoritative artifact.

Generated artifacts are written under a run-id staging directory and promoted
atomically to `workload-v1/` only when fully generated and validated. An
existing published workload is never silently overwritten. Authoritative files
contain no timestamps, absolute paths, machine names, temp directories, random
UUIDs or run ids. Repeated generation from the same corpus, contract and
generator must produce identical logical probes, identical expected results,
identical canonical bytes for authoritative files and the same workload_id.

## Analytical execution

Analytical operations may use native SQL/vectorized/relational execution. The
contract freezes logical input, logical output, correctness digest and
measurement boundaries, not SQL syntax or physical plans. A1 must not be
satisfied by `COUNT(*)` from metadata: the workload forces logical row
processing and a MultisetFoldV1 digest.
